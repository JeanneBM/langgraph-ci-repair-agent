# Live Azure validation: S01 with the policy guard, 2026-11-17

A real model on Azure OpenAI repaired S01. The proposal and the export were authorized by
the v1.0 policy, after an explicit human approval. The lab was deleted and its absence was
verified.

## Setup

- Code: `main` at `eb9dcce` (v1.0), agent-policy-guard pinned to `4ec36af`.
- Local machine: Windows, Git Bash. The test suite on that machine gave `106 passed, 2 skipped`;
  the two skipped tests need a wheelhouse.
- Lab: `scripts/lab.py setup` in a dedicated group `rg-langgraph-ci-repair-demo-2`, region
  `swedencentral`. Azure OpenAI account (S0) with `gpt-4.1-mini` version `2025-04-14`,
  `GlobalStandard`, capacity 10. Entra authentication: no API keys were created or stored.
- Isolation: none. The export was therefore allowed under rule `export-static-demo`, which
  requires `isolated_check = not_run` and static validation.

## Result

| Step | Observed |
|---|---|
| `lab.py run --scenario S01 --thread s01-live-guard` | `awaiting_approval` after 1 attempt |
| Proposal policy (`ci.accept_proposal`) | `allow`, rule `rule-matched-change` |
| Human approval | Given by the repository owner after reviewing the diff |
| Export (`ci.export_patch` through `GuardedExecutor`) | `allow`, rule `export-static-demo`, `binding_ok: true`; status `draft_prepared` |
| Audit file | 3 events (`proposal_decision`, `authorization`, `execution_returned`), all with policy hash `0f66b13b…d08ad664`, the same hash as in [`demo-results.json`](demo-results.json) |
| Cleanup | `lab.py delete` verified the group absent; `az group exists` returned `false` |

The model proposed exactly the expected one-line change:

```diff
-      - run: python -m pip install -r requirement.txt
+      - run: python -m pip install -r requirements.txt
```

Its diagnosis in the exported `draft-pr.md`: the workflow installs dependencies from
`requirement.txt`, but the correct filename is `requirements.txt`, so the installation step
fails because the file does not exist.

## Limits

- One run of one synthetic scenario. It shows that the model-backed path works end to end
  with the policy and guarded export, not that the model diagnoses well in general.
- No isolated run, no remote CI job and no GitHub PR.
- Setup first found an empty, tagged group left over from an earlier lab run
  (`rg-langgraph-ci-repair-demo`). The script refused to reuse it because it had no matching
  local state. The group was deleted separately.
